# Contract — the canonical character image (v2, 2026-10-03)

**v2 supersedes v1 (four directional views).** The producer simplified the identity for this phase:

> one character = one canonical front full-body image + one persistent voice identity.

Domain types on main (`src/domain/types.ts`): `CanonicalImage`, `AssetTier`, `Character.canonicalImage`,
`Asset.tier`. No left, right, back, sheet or extra reference views are generated by default; additional view
generation is added only if it becomes strictly required later.

## 1. The model

- `Character.canonicalImage = { assetId, status: DRAFT | APPROVED, version, jobId, seed, referenceAssetId, engine,
  identityLine, check, generatedAt, approvedAt }`. Storage: a dedicated column `canonical_asset_id` on characters
  (queryable, referentially protected) + `canonical_image` jsonb for the rest.
- **It is the primary image everywhere**: character cards, lists, the detail page, cast displays, selection dialogs,
  production assignment, and the reference given to image/video generation for shots. One selector,
  `primaryImageOf(character)` (canonical, else legacy `portraitAssetId`, else none), used by every one of them.
- **Asset tiers** (`assets.tier`): `CANONICAL` (the canonical image), `SECONDARY` (optional material made on
  request: portrait close-up, expressions, outfits), `RAW` (rejected candidates, previous versions, intermediate
  output). The profile shows the canonical image; SECONDARY lives in an optional, collapsed section; RAW is never
  shown on a profile (Files can filter to it; purgeable).

## 2. Generation (Auto, Manual, Image Reference)

1. **Design** (when fields are missing) → a fixed English identity line: style first, then age, build, face, hair,
   skin, every garment with its colour, accessories (with their side of the body), footwear.
2. **Canonical image**: one front full-body figure — standing, relaxed neutral pose, head to feet in frame with margin,
   plain neutral background, even light, in the production direction (Cartoon / Anime / Realistic). Auto/Manual: from
   the identity line. Image Reference: the uploaded picture guides the look; the identity line is written from a
   description of the picture (never invented).
3. **Checks** only where they demonstrably separate right from wrong (e.g. full body in frame, style); a failing image
   is redrawn once with the reason noted, then left for the producer with the reason.
4. The image is **DRAFT**; the producer approves it (one action) → **APPROVED**, the official identity.
5. Then the voice (the voice identity contract).

Jobs: `CHARACTER_APPEARANCE {characterId}` draws the canonical image (new version; the previous canonical asset
becomes RAW). `CHARACTER_REFS` is kept only for optional SECONDARY material on request and is never part of creation.
`CREATE_CHARACTER` steps: **design → image → voice**, ending "awaiting your approval".

## 3. Rules

- Commands: `setCanonicalImage(characterId, CanonicalImage)` (worker; status DRAFT, version +1, tiers updated),
  `approveCanonicalImage(characterId, version)` (producer; refused for a stale version; a failed check needs
  `override` with a reason recorded), `setAssetTier(assetId, tier)`.
- `APPEARANCE_LOCKED` (server-side) once the character is used in a video: no redraw, no replacement, no approval
  change. Harmless metadata (name, Arabic name, short description/role, personality, notes) stays editable.
- Production preflight warns when a cast character's image is not APPROVED and fails when it has none.

## 4. The character page — a premium cast profile

Built around one main professional image. One page (no tab maze), in this order of attention:
- the canonical front full-body image as the hero;
- name (+ Arabic name), short description, personality, language / dialect;
- **voice identity** (a real player for its sample, origin label, language/dialect, status);
- **lock status** shown once (Draft — awaiting your approval / Approved / Locked: used in N videos, with the reason);
- **productions used in**.
Actions are quiet and contextual: Approve (when DRAFT), Redraw (unlocked only), Edit details. "Secondary material"
(if any exists or is requested) sits in a collapsed section at the end. Raw outputs never appear. The directory,
cast displays and pickers show the same canonical image. Follows `docs/DESIGN-SYSTEM-V3.md`.

## 5. Acceptance

In the browser with real generation: Auto, Manual and Image Reference, in Cartoon, Anime and Realistic — each result
is one front full-body image (head to feet, correct style, matching the description or the reference), approved
through the UI, shown as specified on desktop, phone and in Arabic; a voice identity built and playable; redraw
before use works; after use in a video the server refuses redraw while metadata stays editable.
