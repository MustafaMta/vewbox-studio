# Contract — the canonical character identity pack (2026-10-03)

The producer's direction: character creation produced "too many scattered reference files". A character's identity
is a clean **canonical directional pack** of four full-body views — **Front, Right side, Left side, Back** — and the
character page is a professional cast profile, not a generation queue. Domain types are on main
(`src/domain/types.ts`: `IDENTITY_VIEWS`, `IdentityView`, `IdentityPackView`, `IdentityPack`, `AssetTier`,
`Character.identityPack`, `Asset.tier`).

## 1. The model

- `Character.identityPack` = `{ status: DRAFT | APPROVED, version, views: { FRONT, RIGHT, LEFT, BACK }, identityLine,
  identitySeed, approvedAt }`. **Dedicated storage**: the characters table gets four columns
  `front_asset_id`, `right_asset_id`, `left_asset_id`, `back_asset_id` (the canonical views, queryable and
  referentially protected) plus `identity_pack` jsonb for status, version and per-view metadata (seed, references,
  job, engine, check). The domain object is assembled from both.
- **Sides are anatomical.** RIGHT = the character's own right side faces the camera (they face screen-left); LEFT = their
  left side (they face screen-right). Both are generated — **never a mirror** of the other — so asymmetric details
  (a bag strap on one shoulder, a hair parting, a scar, a watch) stay on the same side of the body. The UI labels them
  "Right side" / "Left side" with the caption "their right / their left".
- **The FRONT full-body view is the primary image everywhere** (directory card, profile hero, casting pickers, shot
  references). `portraitAssetId` becomes an optional SECONDARY close-up.
- **Asset tiers** (`Asset.tier`, a new `assets.tier` column): `CANONICAL` (a view of an identity pack), `SECONDARY`
  (portrait close-up, expressions, wardrobe variants, a turnaround sheet if one is kept), `RAW` (intermediate output:
  a sheet before cutting, rejected candidates, crops). The profile shows CANONICAL by default and SECONDARY in its
  own optional section; RAW never appears on a profile (Files can filter to it; purgeable).

## 2. Generation (default for Auto, Manual and Image Reference)

1. **Design** (when fields are missing) → an English identity line that states style first, then age, build, face,
   hair, skin, wardrobe with every garment and colour, accessories with their side of the body, and footwear.
2. **FRONT** full body: standing, relaxed neutral pose, whole figure head to feet in frame with margin, plain neutral
   background, style-correct (Cartoon / Anime / Realistic), from text (Auto, Manual) or from the uploaded picture
   (Image Reference: the picture guides the look; the vision description, not an invented one, fills the line).
3. **RIGHT, LEFT, BACK** full body from the FRONT view as the reference (the identity seed; same framing, scale,
   background and lighting), each a deliberate view — the same clothes, proportions, colours and style.
4. **Checks** per view against FRONT (style, full body in frame, correct direction, identity details, the
   side-specific details on the correct side) — only checks that demonstrably separate right from wrong are used;
   anything not measurable is reported as such, never as a pass. A failing view is redrawn once with the failure
   noted, then left for the producer with the reason.
5. The pack is **DRAFT**; the producer **approves** it (one action) → APPROVED. Before approval the profile shows the
   views with "Awaiting your approval" and per-view Redraw.
6. Nothing else is generated by default. Portrait close-up, expressions and outfits are optional actions in the
   Secondary section.

Jobs: `CHARACTER_APPEARANCE` draws FRONT (and starts a new pack version); `CHARACTER_REFS` draws the directional views
(`views: IdentityView[]`, default RIGHT/LEFT/BACK) or, with `secondary: [...]`, optional material. `CREATE_CHARACTER`
steps become **design → front → sides → voice**, then waits for approval (the result says "awaiting approval").

## 3. Rules

- Commands: `setIdentityView(characterId, view, IdentityPackView)` (worker), `approveIdentityPack(characterId, version)`
  (producer; refused if any view is missing or a view's check failed without an override), `redrawIdentityView` returns
  the pack to DRAFT. All refused with `APPEARANCE_LOCKED` once the character is used in a video (server-side, as now).
  Profile metadata (name, description, personality, notes, language label) stays editable when locked.
- Reference conditioning for production (later phases) uses FRONT first, then the side matching the shot's direction
  when known; a shot records the pack version it used.
- A character without an APPROVED pack can be cast but production preflight warns ("identity not approved").

## 4. The character page

`/characters/[id]`: the FRONT full-body image as the hero; tabs **Overview · Sides · Voice · Usage** (plus a quiet
"Secondary material" section under Sides when any exists).
- **Overview**: hero image, name (+ Arabic name), description (role), personality, language / dialect, identity
  status (Draft — awaiting approval / Approved / Locked, with the reason and the productions that locked it),
  productions where used.
- **Sides**: Front · Right · Left · Back as one clean, evenly sized row (2×2 on a phone), labelled, approved views
  only by default; per-view Redraw while unlocked; Approve when DRAFT.
- **Voice**: the voice identity (player, origin label, language/dialect, status, lock) per the voice contract.
- **Usage**: productions, shots, takes that use the character, and the pack version each used.
The directory card shows the FRONT full-body view. Everything follows `docs/DESIGN-SYSTEM-V3.md`.

## 5. Acceptance

Real generations in the browser for each creation method (Auto, Manual, Image Reference) and each style (Cartoon,
Anime, Realistic): four full-body views per character, correct directions, identity/clothing/proportions/style held,
approved through the UI, visible as specified on desktop, phone and in Arabic; redraw of one view; lock after use
refuses redraw on the server.
